Type: Fixed

- A start of a child that stalls past its bound now leaves a stack in the slow-start ledger and the daemon's log. After `StartStalled` is raised, a thread of its own samples each child of the daemon that looks stuck, forked and not executed, at most two, with the operating system's sampler on macOS and the process's state and wait from `/proc` on Linux, bounded in time and characters, and the ledger keeps room beyond its limit for these entries. A line can ask for the same for one of its own processes with the new `sample_process` tool, which applies the checks that precede a stop. This is evidence for the macOS stall, whose cause is still unproven.
- The engine drivers and the relay start their children on the event loop through `spawn.subprocess_exec`, which gives them the descriptor handling of `spawn.start`, the sweep inside the fork lock, and refuses a start whose sweep did not run. They are still not bounded, which `dromon.spawn` and the design document say, with the adapter that would bound them left as the follow-up.
- A run launch that is cancelled while its supervisor starts no longer leaves the supervisor running. `ProcessWorker.run` takes a `discard` for a result that no caller will receive, and the run start passes `runs.abandon`. A test fails without it.
- A `ps` that only timed out on every attempt of the check before a `kill_all` turn no longer holds the line for an operator. The turn starts with a note and the mail it delivers is kept, and a `ps` that cannot run or fails still refuses the turn.
- The sandbox document names the one-writer bound that protects a working directory from a line that can write its parent.
- The gate step in continuous integration is bounded at 25 minutes and unbuffered, and the test run reports the running test and its age from 20 minutes on to a copy of the real standard error, so a job that is cancelled leaves a log that names the test. The relay test that bounds the event loop's gap now bounds it by the injected block and not by a constant beside it.
- `list_processes` now says, when the ledger is empty and no process can be identified, whether the daemon holds a launch record for the line's engine, since that record is the only root of the ledger and a line could not tell an engine with no children from one that cannot be looked at.
