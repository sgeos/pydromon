Type: Changed

- The kept-session test of the stale brief notice, which failed once in continuous integration on Linux with Python 3.15, now records every read of the worktree's uncommitted state and puts the record in each assertion message. It also checks that the brief kept a digest when it was set. Nothing is put in front of the notice in that test, so the notice was absent, and a failed read is turned into no comparison without a reason. The next failure therefore names which read failed or what it returned. The cause is still unknown, since the failed log was not read, and this is a test change only. The test of discarded work is given the same record.
- The tests of each failed `git status` read inject the failure into `dromon.spawn`, through which git is now started, and check that the read went through it. A start that stalls is tested too, and gives `not_started`. They had patched `subprocess.run`, which the read no longer calls, so they failed once the spawn helper merged.
- The test that a refusal made while a disclosure check reads withholds the check's answer now holds the check's worker until the refusal is made. A single yield to the event loop had let the check finish first, which was observed about once in twenty runs on Python 3.15, so the test failed without the code being wrong.
