Type: Fixed

- Starts on the event loop are bounded as `spawn.start` is. `spawn.subprocess_exec` made its child on the loop's own thread, so a start that stalled before the program ran stopped the daemon's loop and nothing could end the wait. It now makes the child with `spawn.start` from an executor thread, under the same bound, report, sample, fork lock and descriptor sweep, and wraps it as `BoundedProcess`, which has the members of an asyncio process that the engine drivers and the relay use. A start that passes its bound raises `StartStalled` at the bound with the loop running. A caller cancelled while its child is made has the child ended and reaped. A test forbids any module from calling asyncio's own start.
- The launcher sweep told a harness and its launcher from another process by their names, so a pid given to another process with the recorded name was ended, a harness that replaced itself with a program of another name was never swept, and a launcher pid held by another launcher was taken as running. The launcher now records when it and its harness started, from the kernel, and the sweep tells them by that, reads the start time again immediately before each signal, so a pid reused after the table was read is not signalled. The sweep reads its table with start times.
- The bounded process for an `asyncio` caller now closes the pipe to its child when the child exits, as `asyncio` does, since a descendant that inherited the pipe, such as a launcher's harness, kept it open and the writer was reported as a `ResourceWarning` when collected.
- A start time that is missing or cannot be read now fails closed wherever a signal follows. A launch record written before round 18, which has no start times, signals nothing, so at the first restart onto this version an older launcher that is still running is left alone and one that has exited has its record removed with the reason said and nothing signalled. A process group is signalled only when its leader is gone, is a zombie the table showed, or started when the record says. A launcher or harness whose start time cannot be read is taken as held and not swept, and a listed row without a start time is not signalled.
- The exec-wait monitor no longer dies silently on an exception. It records the first failure once and goes on, looks at each fork on its own, and is started again by the next fork if it has ended.
- The bounded starts of `spawn.subprocess_exec` run on a pool of their own, at most 16 threads and 64 waiting, and no longer share the loop's default executor, so a burst of slow starts does not delay an unrelated `asyncio.to_thread` call. A caller cancelled while its child is made has it ended by the thread that made it, with no dependence on the loop.
- The launch smoke check's verdict is tested branch by branch, with three mutations that survived now failing a test, and it asks `launcher_running` with the record's start times as the sweep does.
