Type: Fixed

- Starts on the event loop are bounded as `spawn.start` is. `spawn.subprocess_exec` made its child on the loop's own thread, so a start that stalled before the program ran stopped the daemon's loop and nothing could end the wait. It now makes the child with `spawn.start` from an executor thread, under the same bound, report, sample, fork lock and descriptor sweep, and wraps it as `BoundedProcess`, which has the members of an asyncio process that the engine drivers and the relay use. A start that passes its bound raises `StartStalled` at the bound with the loop running. A caller cancelled while its child is made has the child ended and reaped. A test forbids any module from calling asyncio's own start.
- The launcher sweep told a harness and its launcher from another process by their names, so a pid given to another process with the recorded name was ended, a harness that replaced itself with a program of another name was never swept, and a launcher pid held by another launcher was taken as running. The launcher now records when it and its harness started, from the kernel, and the sweep tells them by that, falls back to the name for a record without it, and reads the start time again immediately before each signal, so a pid reused after the table was read is not signalled. The sweep reads its table with start times.
- The bounded process for an `asyncio` caller now closes the pipe to its child when the child exits, as `asyncio` does, since a descendant that inherited the pipe, such as a launcher's harness, kept it open and the writer was reported as a `ResourceWarning` when collected.
