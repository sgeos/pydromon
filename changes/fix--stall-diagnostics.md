Type: Added

- A start that stalls past its bound now says what it can. `StartStalled` carries a report, also written to the daemon's standard error, of where the start's thread is in Python, how many starts were in flight together, how many threads are alive, and each child of the daemon with its state, its program name, whether it has executed and what it waits on, read from `/proc` on Linux and from `ps` elsewhere. It names no argument, shows only printable ASCII and is at most 1200 characters. No cause of the stall is fixed. The module records a reading of every start site and three further hypotheses.
- The daemon now dumps the traceback of every thread when a child start is still stuck five seconds past its bound, from `faulthandler`'s timer, which needs no interpreter lock and so fires even when the stuck start has frozen every Python thread. This is `spawn.watch_starts`. It is off outside the daemon, and tests leave it off because `faulthandler` keeps one timer per process.
- The tests stop the process workers of every scheduler they build and fail if a worker thread outlives its test. A hung Linux run had left 99 idle workers, which filled the 100 threads that `faulthandler` shows and hid the main thread. A late-start test also waited for a child with no pipe before its reap had killed it, and failed about one run in six. It now waits until the child has ended.
- Every child start in the daemon process is now made under one lock, so no two threads fork at the same moment. `spawn.install_fork_lock` puts it around `subprocess._fork_exec`, `os.posix_spawn` and `os.posix_spawnp` at import, which covers the engine drivers, the relay and the launcher as well as `spawn.start`. Nothing else is held across the fork. A start that waits 30 seconds for the lock is refused with `StartStalled`, and the watchdog times each fork. Whether this ends the intermittent stall is not yet known.
- The stall report reads the daemon's children from `libproc` on macOS, which starts no process, so it works inside an agent's sandbox and when the stall has left the process unable to start `ps`. A child still being created shows state `I`.
