Type: Fixed

- Every child process the daemon starts, apart from the launcher's harness and the engine drivers' asynchronous starts, now goes through one module, `dromon.spawn`, which bounds the start as well as the run. `subprocess.run` and `Popen` wait for the child to reach `exec` with no bound, and on macOS that wait stalled a gate for its five minute limit in several tests. A start that does not end within `START_SECONDS` now fails at once with `StartStalled`, which is an `OSError`, with a message naming the program and the bound. A child that starts late is killed and reaped, at most four stuck starts are tolerated, and descriptors handed over with `close_after` are closed only once the start has ended. The git runners of the staleness worker, the worktree status and `dromon land`, and the test helpers that call git or `ps`, use it. The cause of the stall is not found, and the module records what is known. A test names the modules left out, so the residual cannot grow unseen.
- The byte bound on a line's temporary directory purged a directory of more than 100,000 entries to its oldest ten thousand whatever its size. Removal now starts only when the counted bytes already exceed the bound, stops at half of it, ages an entry by the latest change inside it, and reports a directory it could not measure in full.
- The ledger of a line's children is rooted at the engine a launch record names only if the process holding that pid is still that engine. Its command must hold the recorded executable and it must have started no later than the record was written, so a record left not done by a dead launcher cannot enter the children of a process that reused the pid. A record with no time, or a start that cannot be read, roots nothing.
- The event log now fails closed when the source of literal secret values raises. An event with text is refused with `SecretsUnavailable`, an `EventRejected` whose message names the kind of failure and never its text, and nothing is stored, where it was stored masked by pattern alone. The source is asked only for an event that has a covered field.
- The patterns that mask the user and password of a URL, and of `user:password@host` without a scheme, now mask a password that holds `@` whole, and in a URL one that holds `/`. A password that begins like a port and a path, a digest reference, an address and `host:dir/file@name` are left alone. A scheme-less password with `/` is still not masked, since it cannot be told from a path.
