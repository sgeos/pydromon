Type: Fixed

- A line whose working directory is a link to another volume can write it, because the sandbox settings now grant the real path of the working directory, and each deny entry, protected directory and guarded path is kept as written and given its real path too, since the sandbox follows a link before it matches a rule. An allow entry is not given a real form, so a line that re-links an allowed directory it can write gains nothing. `docs/protocol/SANDBOX.md` records the rule and its residual.
- A cancellation that arrives while a run parameter matcher is still starting its child no longer leaves that child running, however many cancellations arrive. `runparams.match` now waits for the start, kills and reaps the child and closes its pipes, which a loaded gate run showed as one failed test and a child still running at teardown.
- A diagnostic line about a slow or stalled child start can no longer hold the start. It is written after the outcome is handed over, by one thread of its own that the start waits for at most a second, lines that arrive meanwhile are queued, up to sixteen, and not dropped, with a rate-limited line going first when the queue is full, and a slow-start line is written at most once a second. A start made on an event loop's own thread waits five seconds for the fork lock and not thirty, a start nested in a start is refused at once, and the stall message names the program by its base name only.
- Linux children are started with `vfork` again, as CPython does, because turning it off did not stop the continuous integration timeouts and makes every start copy the daemon's page tables. `DROMON_NO_VFORK=1` turns it off for a run that compares the two.
- The child starts of the launcher tests now go through `spawn.start` and `spawn.run`, so a start that stalls on macOS fails within its bound with a report of the child and not at the five minute timeout of the whole run. A test keeps direct `subprocess` calls out of that file.
- On macOS a child started through `spawn.start` no longer enumerates `/dev/fd` after the fork, which the child that stalled during a gate had open as a directory and was most likely stopped in. The parent clears every inheritable descriptor above 2 that is not passed on purpose and starts the child with `close_fds` off, which also lets `subprocess` use `posix_spawn`. The sweep and the marking of a passed descriptor happen inside the fork lock, just before the fork, and the marking ends when the fork call returns or fails, so no other start's child and no start that stalled before its fork holds it. Tests show that an inheritable descriptor does not reach the child. `DROMON_CHILD_CLOSES_FDS` set to `1` or `0` forces either setting, and the slow-start ledger records which one a start had. Whether this removes the stall is not known.
- A child start that runs longer than five seconds now writes one line, and records it in the slow-start ledger, naming every thread, its processor time on Linux and its innermost three frames, so that a continuous integration log of a slow start shows which thread held the processor.
