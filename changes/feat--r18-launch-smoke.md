- A launch smoke check starts a stand-in harness of each of the six engine kinds under both stop policies through the function that the engine's adapter starts its harness with, so the same launcher and module command run and no model does. It runs the daemon's own sweep twice while the launchers live and requires that the sweep ended nothing, removed no record, and left every launcher and harness running and recognised. The gate runs it, and the restart preflight runs it after the engine startup checks, so a successor whose launcher the sweep would end is refused before the running daemon stops. Where the process table cannot be read, as in an agent sandbox, the check says so and does not count a pass, and the gate's tests give the sweep a model of the table built from the launch records. It would have caught the defect that pull request 157 shipped, which a test shows by putting the truncated marker search back.
- A process start time, read from the kernel without starting a process, and signals that check it, `signal_if_started` and `signal_group_if_started`, which on Linux hold the process by a pidfd for the signal.
- The exec wait of every start is timed. A child that has been forked and has not executed three seconds later, as shown by its starting thread still being inside `subprocess`'s `_execute_child`, is sampled and recorded in the ledger as `exec wait`, and written to the daemon's log, whoever made the start. This covers the direct `Popen` whose hang of five minutes the existing bound and ledger could not see.
- The tests start their children with `spawn.start` and `spawn.run`, and a scan of the tests fails for a function that starts a child directly and is not named, with its reason, in `tests/test_tests_use_spawn.py`.
